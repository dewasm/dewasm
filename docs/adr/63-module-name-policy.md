# ADR-63 — `--module-name`: Fixed in Standalone, Validated Verbatim in Library Mode

Status: **Accepted, 2026-08-05.** Landed for Ruby, Python, Perl, Bash, Java and the CLI: the five copies of the PascalCase sanitizer (and Bash's snake analogue) are deleted, a standalone artifact's internal name is fixed, and a library-mode name is used exactly as given or refused. Go follows the same rules; its rows below are the contract, implemented separately. The kebab-case derivation the test suites now use lives in `crates/dewasm-test-helper/src/backend.rs` — test infrastructure, not a product surface.

## Context

`--module-name` (default: the input file stem) named the generated class/package/prefix. Each backend then ran its own copy of a lossy sanitizer: uppercase every alphanumeric run, drop everything else, prepend `Wasm` if the result was empty or digit-initial (`crates/dewasm-backend-{ruby,python,perl,java,go}/src/lib.rs`, `class_name`/`package_name`/`type_name`; Bash's `func_prefix` did the snake-case equivalent). Nothing was ever rejected.

So `sqlite3-shell` became `Sqlite3Shell`, `a.b.c` became `Abc`, `--` became `Wasm`, and `hello_world` and `HelloWorld` became the same class. The rule was not written down anywhere, and it could not be — it is five slightly different rules that only agree by accident. A user who asks for a name and gets a different one has to read the backend source to find out what they will get, and every future namespacing feature (a Java package, a Ruby constant path) has to be squeezed through a transformation that has already thrown the relevant characters away.

The two modes also do not have the same problem. A `--mode standalone` artifact is a self-contained program: its class name appears nowhere in any interface, and asking a user to name it is asking a question with no right answer — while forcing every backend to answer awkward variants of it (does a dotted Java name mean a package for a program whose entry point must be `Main`?).

## Decision

**1. A standalone artifact's internal name is fixed.** Ruby/Python `class Program`, Perl `package Program`, Java module class `Program` (the driver stays `public class Main`), Bash prefix `program_`, Go `package main` with type `Program`. Passing `--module-name` together with `--mode standalone` is a conversion-time error naming the mode. The CLI hands the backend the fixed placeholder `program` in that mode, which names only the output *file* label, so converting any `.wasm` standalone needs no name at all.

**2. A library-mode name is required, and used verbatim or refused — never transformed, never defaulted.** `--module-name` is mandatory in library mode: the input file's name on disk says nothing about what the caller wants the embedded API to be called, so there is no default to derive. The discriminating criterion, and the reusable rule: *a specification whose correct behaviour cannot be predicted from the input must not exist.* An implicit transformation is a permanent maintenance burden — it has to be preserved for compatibility long after anyone remembers why it maps what it maps. Validation is the opposite: the grammar is one line of documentation, the failure is at conversion time with the offending value in it ([ADR-0](0-foundation.md)), and the fix is obvious.

| Backend | Library-mode grammar | Emitted as |
| --- | --- | --- |
| Ruby | `::`-separated segments, each `[A-Z][A-Za-z0-9_]*` | `class A::B::C`, preceded by guarded ancestor definitions |
| Perl | `::`-separated segments, each `[A-Za-z_][A-Za-z0-9_]*` | `package A::B::C`, runtime under `A::B::C::Rt` |
| Python | one identifier `[A-Za-z_][A-Za-z0-9_]*` | `class Name`, runtime `class NameRt` ([ADR-62](62-embedded-runtime-isolation.md)) |
| Java | `.`-separated segments, each `[A-Za-z_$][A-Za-z0-9_$]*` | leading segments → `package a.b;` first line, last segment → the class name |
| Bash | one identifier `[A-Za-z_][A-Za-z0-9_]*` | prefix = the name **lowercased** + `_` |
| Go | one identifier `[A-Za-z_][A-Za-z0-9_]*` | `package <lowercased>`, type = first letter capitalized |

Four details the grammars imply:

- **Ruby's guarded ancestors.** `class A::B::C` requires `A` and `A::B` to exist, and a generated file must load both standalone and beside a program that already defined them. Each ancestor therefore gets `unless defined?(A)` / `module A; end` / `end`, outermost first. Verified against real Ruby: a module-in-`unless` parses at top level; an ancestor that already exists *as a class* is skipped by the guard and kept intact; an ancestor bound to a non-module constant fails loudly at load with `TypeError`, which is the right outcome. A single-segment name emits no guards, so its output is byte-identical to before.
- **Java's split rule.** The last dot-separated segment is the class name, used verbatim; anything before it is the package declaration, emitted as the file's first statement (ahead of the bundled runtime classes, which share the compilation unit per [ADR-30](30-java-backend-lowering.md)). `com.github.dewasm.Ruby` is how a caller gets both a conventional package and a conventional class name — which is also why the class segment is not forced to be capitalized. The grammar is character-level only: a segment that happens to be a Java keyword (`int`, `package`) or a restricted type name (`var`, JLS 8.1) passes validation and fails in `javac` with the compiler's own message. A maintained keyword list was rejected — it is exactly the kind of continuously-maintained language-specific table this ADR exists to avoid, it drifts as the language evolves, and the compiler already produces a clear error at the same fail-loud stage of the workflow.
- **Bash's lowercase exception.** Bash has no case-carrying namespace — every generated name is a global shell identifier — so the prefix is the name lowercased. This is the one deliberate mapping the policy keeps, and it is admissible precisely because it is total and fully specified: `Sqlite3Shell` → `sqlite3shell_`, always, with no information the caller needs back.
- **Go's `--module-name main` is accepted.** It yields `package main`, which no other package can import. That is allowed rather than special-cased: `main` is a Go identifier and the grammar is the whole rule, so adding one blocked word would mean the name is *not* used verbatim after all. It also has a real use — dropping the artifact into a `package main` program next to a hand-written `func main`, the shape the Go library output had before this ADR. The failure mode if the caller meant something else is a Go compile error (`function main is undeclared in the main package` or an unimportable path), not a silent wrong artifact.

**3. Kebab-case derivation is test infrastructure.** The test and tooling world names things in kebab/stem case (`sqlite3-shell`, `ruby-packed`, `prog`) and now has to hand each backend a name in that backend's grammar. `BackendUnderTest::module_name` (defaulting through `derive_module_name`, `crates/dewasm-test-helper/src/backend.rs`) converts `[a-z0-9]+(-[a-z0-9]+)*` to PascalCase, panicking outside that domain; Bash alone takes snake_case, because its prefix is the name lowercased and `sqlite3_shell_` is what its glue spells. Go takes Pascal despite its lowercase package clause: it builds *both* names out of the one string, and only a Pascal input yields a conventional pair (`Sqlite3Shell` → `package sqlite3shell`, `type Sqlite3Shell`). The derivation reproduces exactly the names the deleted sanitizers produced for these inputs, so the per-language glue constants keep working. It lives in the test helper on purpose: the product performs no name transformation at all, and a convenience that only test tables need must not become a CLI behaviour nobody can remove later.

## Rejected alternatives

- **Keep sanitizing, but write the rule down.** The rule is unwritable as one rule (five variants), and documenting a lossy mapping does not make its inverse exist: the user still cannot ask for `hello_world` and get it. It also blocks the namespacing the grammars now allow — a sanitizer that deletes `:` and `.` cannot ever grow a Ruby constant path or a Java package.
- **Sanitize, but warn on stderr.** A warning is not an error: CI pipelines swallow it, and the artifact still has a name the user did not ask for. ADR-0's rule is that a request the converter cannot honour fails at conversion time.
- **Let `--module-name` work in standalone mode too** (naming the internal class). It answers a question no user has, and it forced the Java dotted-name question — a `package` for a program launched as `Main` — into a decision with no good answer. Fixing the name deletes the question.
- **Default the library-mode name from the input file stem.** Rejected: it couples the generated API's public name to how the input file happens to be stored — rename the file and the class changes — and it resurrects a mode-and-backend-dependent surprise (a stem valid for Python but not for Ruby converts on one target and errors on the other). A concept whose correct behaviour cannot be predicted from the request alone should not exist; requiring the flag makes every library conversion say what it means.
- **Do the kebab derivation in the CLI** (accept kebab-case and convert). That is the sanitizer again, with a smaller input domain. The test suites need it because their case tables are keyed by cache stem; users type the name they want.

## Consequences

- Positive: what the caller writes is what the artifact is called. Ruby gains constant paths and Java gains packages with no new flags — they fall out of the grammars. The generated output is byte-identical for every name that was already valid (single-segment Pascal names, which is every name the repo passed).
- Negative: every library-mode conversion must now pass `--module-name` (`dewasm add.wasm --mode library` alone is an error). `examples/rails/build.sh` and the library walkthroughs in `README.md` and `docs/getting-started.md` spell it out; the `examples/{doom,nes}/*/build.sh` scripts already passed one.
- Negative: the module name's meaning is mode-dependent (an internal name in library mode, only an output filename in standalone). The CLI's standalone rejection is what keeps that from being discovered by surprise.
- The benchmark suite converts standalone only, so its per-workload `module_name` had no effect on any artifact and was deleted rather than derived (`crates/xtask/src/bench/`).
- Carry-over: the Go backend implements the same rules in its own change, where it carries a crate-local `common::go_module_name` plus a `GoConvert` newtype to derive names for the shared suites. Those are the Pascal derivation above, spelled twice; once both changes are in, they collapse into `derive_module_name`/`BackendUnderTest::module_name` with no behaviour change.
